## <code>01</code> — hey, welcome in! 👋

So, what's this place?

We're a group of students learning competitive programming one algorithm, one problem, and one mistake at a time.

The Syntax Collective is our shared workspace for exploring computer science, practicing problem-solving, and documenting the things we learn along the way.

You'll find algorithm explanations, data structure implementations, reusable code templates, and solutions to problems from competitive programming platforms.

We don't claim to know everything.

**We're here because we're learning together.**

## <code>04</code> — how we do things 🧠

We believe that understanding an algorithm matters more than memorizing its implementation.

That's why we try to document the reasoning behind our code.

Our algorithm entries generally cover:

- **Purpose:** What does the algorithm accomplish?
- **Prerequisites:** What should you understand beforehand?
- **How it works:** What's happening behind the scenes?
- **Implementations:** How can it be written in Python and C++?
- **Complexity:** How efficient is it, and why?

For problem solutions, we focus on the approach, reasoning, correctness considerations, and complexity analysis.

We want our repository to be useful not only to someone looking for code, but also to someone trying to understand it.

## <code>05</code> — our philosophy 💡

A few things we believe in:

**Learn in public.**

It's okay to be a beginner. Documenting what you learn helps you understand it better and gives others something to learn from.

**Understand, don't just submit.**

An accepted solution is great. Knowing why it works is even better.

**Build together.**

Everyone has something to contribute. A useful explanation, a bug fix, a code review, or a completely new implementation can all make the collective better.

**Stay curious.**

There is always another problem to solve and another concept worth exploring.

## <code>06</code> — want to contribute? 🤝

You're welcome to explore, suggest improvements, report mistakes, or contribute something you've learned.

You don't need to be an expert.

If you're interested in joining the learning process:

1. Explore the repository.
2. Find something you'd like to improve or contribute.
3. Read our [contribution guidelines](CONTRIBUTING.md).

We appreciate thoughtful contributions, constructive reviews, and people who are willing to learn alongside us.
